## How to Test with Wazuh

### Prerequisites

1. **Configure API Keys** in your `.env` file:
   ```bash
   ABUSEIPDB_API_KEY=your_abuseipdb_api_key_here
   OTX_API_KEY=your_otx_api_key_here
   ```

2. **Install Dependencies**:
   ```bash
   pip install -r requirements.txt
   ```

3. **Prepare Wazuh Test Data**:
   - Use the sample file: `data/sample_wazuh_alerts.json`
   - Or create your own test alerts with IP addresses

### Method 1: Test with Sample Wazuh Alerts (Recommended)

This is the easiest way to test the debug logs without requiring a live Wazuh installation.

```bash
# Run the threat intelligence pipeline with sample Wazuh alerts
python main.py --source wazuh --test-data data/sample_wazuh_alerts.json
```

**What happens:**
1. The system reads Wazuh alerts from the sample file
2. Extracts IOCs (IP addresses, domains, hashes, etc.)
3. Enriches each IOC using AbuseIPDB and OTX providers
4. **Debug logs will be printed to the terminal** showing:
   - Requests sent to AbuseIPDB/OTX
   - Responses received
   - Any errors encountered

### Method 2: Test with Live Wazuh (File-based)

If you have Wazuh installed and generating alerts:

```bash
# Point to your Wazuh alerts file
python main.py --source wazuh
```

**Configuration** (in `.env`):
```bash
WAZUH_ALERTS_PATH=/var/ossec/logs/alerts/alerts.json
```

**What happens:**
1. The WazuhConnector monitors the alerts file
2. New alerts trigger IOC extraction and enrichment
3. Debug logs appear in real-time as alerts are processed

### Method 3: Test with Live Wazuh (API-based)

For real-time API integration:

```bash
python main.py --source wazuh --use-api
```

**Configuration** (in `.env`):
```bash
WAZUH_API_URL=https://localhost:55000
WAZUH_API_USER=wazuh-wui
WAZUH_API_PASSWORD=your_password
```

### Method 4: Continuous Monitoring

To continuously monitor and see debug logs in real-time:

```bash
python monitor.py --source wazuh --interval 30
```

This will:
- Check for new Wazuh alerts every 30 seconds
- Process them through the threat intelligence pipeline
- Display debug logs for each API call

### Troubleshooting

#### No debug logs appearing?

1. **Ensure the server is using the updated code**:
   - Stop the server (Ctrl+C)
   - Restart with: `python app.py` or `uvicorn app:app --reload --host 0.0.0.0 --port 8000`
   - The `--reload` flag ensures code changes are picked up automatically

2. **Check API keys are configured**:
   ```bash
   cat .env | grep -E "ABUSEIPDB_API_KEY|OTX_API_KEY"
   ```

3. **Verify providers are enabled** in `config.py`:
   ```python
   ENABLED_PROVIDERS = ["abuseipdb", "otx"]
   ```

4. **Check IOC extraction is working**:
   - Ensure Wazuh alerts contain extractable IOCs (IPs, domains, hashes)
   - Look for "Extracted IOCs" in the logs

5. **Verify logging is configured correctly**:
   - The app.py now includes: `logging.getLogger("intelligence.threat_intel").setLevel(logging.INFO)`
   - Logs will appear with format: `timestamp - module - level - message`

#### API errors in debug logs?

1. **401 Unauthorized**: Check your API keys are valid
2. **429 Rate Limited**: You've exceeded API rate limits, wait and retry
3. **Connection errors**: Check network connectivity and firewall rules

## Using app.py (FastAPI) with Wazuh

The `app.py` file provides a REST API interface for the threat intelligence platform. You can use it to investigate Wazuh alerts via HTTP requests.

### Step 1: Start the FastAPI Server

```bash
# Start the server
python app.py

# Or using uvicorn directly
uvicorn app:app --reload --host 0.0.0.0 --port 8000
```

The server will start at `http://localhost:8000`

### Step 2: Access API Documentation

Open your browser and navigate to:
- **Swagger UI**: http://localhost:8000/docs
- **ReDoc**: http://localhost:8000/redoc

### Step 3: Test with Wazuh via API

#### Method A: Using Wazuh Connector with Test Data

**Endpoint**: `POST /investigate/connector/wazuh`

**Using curl**:
```bash
curl -X POST "http://localhost:8000/investigate/connector/wazuh?test_data=data/sample_wazuh_alerts.json"
```

**Using Python requests**:
```python
import requests

# Test with sample Wazuh alerts
response = requests.post(
    "http://localhost:8000/investigate/connector/wazuh",
    params={"test_data": "data/sample_wazuh_alerts.json"}
)

print(response.json())
```

#### Method B: Using Wazuh Connector with Live Data

**Endpoint**: `POST /investigate/connector/wazuh`

```bash
# Without test data (uses configured Wazuh alerts path)
```

**Configuration required** (in `.env`):

### Complete Workflow Example

Here's a complete example using Python:

```python
import requests
import time

# Start the server first: python app.py

BASE_URL = "http://localhost:8000"

# 1. Check health
print("Checking API health...")
health_response = requests.get(f"{BASE_URL}/health")
print(f"Health: {health_response.json()}")

# 2. Get configuration
print("\nGetting configuration...")
config_response = requests.get(f"{BASE_URL}/config")
print(f"Config: {config_response.json()}")

# 3. List connectors
print("\nListing connectors...")
connectors_response = requests.get(f"{BASE_URL}/connectors")
print(f"Connectors: {connectors_response.json()}")

# 4. Investigate with Wazuh test data
print("\nStarting investigation with Wazuh test data...")
print("Watch the server terminal for debug logs!\n")

investigate_response = requests.post(
    f"{BASE_URL}/investigate/connector/wazuh",
    params={"test_data": "data/sample_wazuh_alerts.json"}
)

# 5. Check results
if investigate_response.status_code == 200:
    result = investigate_response.json()
    print(f"\nInvestigation completed!")
    print(f"Success: {result['success']}")
    print(f"Events processed: {result['events_processed']}")
    print(f"Campaign ID: {result.get('campaign_id', 'N/A')}")
    
    if result.get('response_actions'):
        print(f"\nResponse actions taken: {len(result['response_actions'])}")
        for action in result['response_actions']:
            print(f"  - {action}")
else:
    print(f"Error: {investigate_response.status_code}")
    print(f"Details: {investigate_response.text}")
```

### Available Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/` | GET | Health check and API info |
| `/health` | GET | Detailed health check (Neo4j, ChromaDB) |

| `/investigate/connector/{connector_name}` | POST | Investigate events from connector |

| `/config` | GET | Get current configuration |

### Troubleshooting

**Server won't start?**
```bash
# Check if port 8000 is already in use
lsof -i :8000

# Use a different port
uvicorn app:app --reload --host 0.0.0.0 --port 8001
```

**No debug logs appearing?**
- Ensure API keys are configured in `.env`
- Check that events contain extractable IOCs
- Verify the investigation is completing successfully

**Connection refused?**
- Ensure the server is running
- Check firewall rules
- Verify you're using the correct host/port
