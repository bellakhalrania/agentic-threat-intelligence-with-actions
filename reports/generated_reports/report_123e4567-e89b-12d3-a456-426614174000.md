The outbound connection suggests the attacker is establishing a command‑and‑control (C2) channel or exfiltrating data. No clear objective or payload delivery was confirmed, and the overall confidence in the campaign assessment is **0.5** (moderate).

## Recommendations  

1. **Immediate Network Controls**  
   * Block outbound traffic from `10.0.5.21` to `185.44.12.7` unless a legitimate business need is verified.  
   * Deploy a next‑generation firewall rule to drop traffic to known data‑center IP ranges unless whitelisted.

2. **Endpoint Hardening**  
   * Enforce PowerShell execution policies (`-ExecutionPolicy Restricted`).  
   * Enable Windows Defender ATP or equivalent to detect Base64‑encoded PowerShell payloads.  
   * Disable or restrict the creation of scheduled tasks for non‑admin users.

3. **Monitoring & Detection**  
   * Correlate Sysmon `powershell.exe` events with outbound connections in real time.  
   * Watch for registry modifications under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` and `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`.  
   * Log and alert on any new scheduled‑task creation, especially those set to run under SYSTEM or admin accounts.

4. **Threat Hunting**  
   * Search for other hosts with similar PowerShell execution patterns.  
   * Investigate any files or scripts downloaded from `185.44.12.7`.  
   * Examine the content of the Base64 payload for known malicious modules or obfuscation techniques.

5. **Incident Response**  
   * If the scheduled task or registry run key is confirmed malicious, isolate the host, perform a full disk image, and conduct a forensic analysis.  
   * Preserve all logs (Sysmon, Suricata, Wazuh) for chain‑of‑custody.

6. **Information Sharing**
